## Agent Brief

**Category:** enhancement
**Summary:** Deduplicate Artikel field fallbacks and blog URL building, validate `related`, and count hyphenated Indonesian words as one word.

**Current behavior:**
- Every consumer of an `Artikel` repeats the same fallbacks: the cover falls back to its Kategori's cover, the SEO title falls back to the title, and the Kategori is looked up with a non-null assertion. At least four places (route metadata, the Artikel page component, the Artikel detail data function, the Artikel card data function) do this by hand.
- The Kategori page path (`/blog/kategori/{slug}`) and the Penulis page path (`/blog/penulis/{slug}`) are built with template literals in breadcrumbs, Artikel detail data (including an absolute URL in the `BlogPosting` JSON-LD), listing data (pagination base paths and section links), Artikel Terbaru data, the sitemap, and the Kategori/Penulis routes' canonical metadata.
- `validateArtikel(entries, bodySlugs)` checks slugs, focus keywords, bodies, title/description lengths, and published fields, but ignores `related`. `getRelatedArtikel` drops unknown slugs without an error, so a typo in `related` ships silently.
- `getWordCount(slug)` replaces `-` with a space before splitting, so every hyphenated word counts as two. Indonesian reduplication (`anak-anak`) is common, so counts run high. The existing `ponytail:` comment says counts are approximate but does not mention this.

**Desired behavior:**
- One function resolves an `Artikel`'s Kategori, cover, and SEO title, and every consumer above uses it. The `!` assertion on the Kategori lookup lives in one place (the build already validates Kategori slugs through the `KategoriSlug` type).
- One pair of helpers returns the Kategori page path and the Penulis page path from a slug. Every place listed above uses them; absolute URLs prefix `siteUrl` to the helper's result. Rendered HTML, metadata, sitemap, and JSON-LD stay byte-for-byte the same.
- `validateArtikel` returns an error when an entry's `related` has more than 3 slugs, and an error for each `related` slug that matches no entry in the list (check against all entries, not only earlier ones, since `related` may point forward).
- `getWordCount` treats `anak-anak` as one word. Standalone Markdown punctuation (list markers `-`, `*`, `>` and table pipes) still counts as zero words: only tokens with at least one letter or digit count.

**Key interfaces:**
- `Artikel` type and `getKategori(slug)`: the new resolver takes an `Artikel` and returns at least `{ kategori, cover, seoTitle }`. Follow the repo's data pattern (see `AGENTS.md`); put it next to the existing Artikel lookups.
- `validateArtikel(entries: Artikel[], bodySlugs: string[]): string[]`: same signature, new error messages for `related`. Extend the existing Artikel validation test with one case per new rule.
- `getWordCount(slug: string): number`: same signature; keep the per-slug cache. Update the `ponytail:` comment so it no longer implies hyphens are a known approximation.
